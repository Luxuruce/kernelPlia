# 演示索引

**10 条条款单元 · 10 条链接 · 1 条冲突 · 3 条用例。**

这不是完整索引，是**够把机制跑起来的一小片**。完整索引是另一侧的资产——
一百多条逐条具名采纳的条款单元、它们之间的关系、已发现的官方文件互相打架之处，
以及「什么叫答对」的口径。那部分不在这个仓库里，也不打算放进来。

## 为什么是这十条

它们同时覆盖三条机制，缺一条就演示不出来：

| | 演示切片里的例子 |
|---|---|
| `derogates` 无条件必扩 | 第 70(3) 条减损第 5(4) 条的重金属限值——只答限值不带减损，本来豁免的人会得到错误结论 |
| `explains` 反向上扩 | FAQ 第 III 章问 17 解释第 5(4) 条——命中 FAQ 要把法条带回来，否则答案只剩「无法律约束力」 |
| 冲突暴露并阻断 | 授权决定 2026/429 豁免了托盘缠绕膜的重复使用义务，而官方实施指南没反映 |

## 字段是怎么筛的

**白名单导出，不是黑名单剥离**（见 `tools/export_demo_index.py`）。

黑名单（「记得删掉 notes」）是 fail-open：内容侧以后新增一个敏感字段，默认就跟着泄露。
白名单是 fail-safe：不在那几行里的字段，一个都出不去。`text_zh`（工作译本）、
`notes`（内部答题纪律）、`forbid`（「什么叫答对」）都不在白名单里，所以不在这里。

`text_en` 在——那是欧盟公报的**作准原文**，本就公开。

## 两个必须带上的限定

1. **译本无法律效力。** 欧盟官方语言 24 种不含中文，本法规没有中文作准文本。
   `heading` 是工作译文，**以英文原文为准**。
2. **`adopted_by` 写的是「演示切片（非真实采纳记录）」。** 真实索引里那一栏是具名的人，
   因为「只有具名采纳的条款可进检索」是这个系统的一条硬约束，演示切片不冒充它。
