# kernelPlia

**一个法规问答内核。它的设计目标不是「答得像」，是「答错的时候答不出来」。**

给定一个用大白话问的合规问题，它给出结论、并把每一条结论钉回具体的条、款、项——
可以点开看官方公报的原文页，被引的那几行有高亮框。

以欧盟包装法规（PPWR，Regulation (EU) 2025/40）为第一个语料实现。

```
提问 ──► 条款号精确定位 ──► 主题词召回 ──► 一跳链接扩展 ──► 冲突判定
                                                              │
                                            ┌─────────────────┴──────────┐
                                          命中                          未命中
                                            │                            │
                                     暴露并阻断                    上下文装配
                                   （不调模型）                  （10K/15K 闸门）
                                                                         │
                                                             结构化输出 + 六条服务端校验
                                                                         │
                                                              条款级引用 · 位阶分级 · 原文页高亮
```

---

## 三个不太常见的设计

### 一、「无引用即不输出」是 schema 保证，不是提示词祈祷

答案对象里 `citations` 是**必填字段**，由结构化输出（`json_schema` + strict）在生成阶段强制。
这和「JSON 模式」不是一回事——后者只保证输出是合法 JSON，不保证字段、必填、枚举符合约定。

模型仍可能编条款号，所以后面还有六条服务端校验，每一条对着一条具体的红线：

| | 校验 |
|---|---|
| 1 | 知识模式无引用 → **不输出**，走兜底文案 |
| 2 | 引用的条款号必须**在库中存在且已具名采纳**，编的直接丢弃；全编则不输出 |
| 3 | 引用按**效力位阶升序**重排，位阶以库为准——模型把 FAQ 标成位阶 1 也不算数 |
| 4 | 位阶 3、4 由服务端补上「委员会解释、无法律约束力」标注 |
| 5 | 声称「官方文件未覆盖」却没给推理说明 → 不输出 |
| 6 | 命中已知冲突 → 不出答案正文 |

**宁可不答，不可无据而答。**

### 二、冲突暴露并阻断，不自动择一

官方文件之间会打架。比如一份授权决定豁免了某类包装的重复使用义务，而三个月后发布的
官方实施指南三节都没提这个豁免。

多数系统会挑一个答案给你。这个内核**不出答案正文**——先把两份来源、各自的效力位阶、
以及位阶指向哪一边摆出来，用户确认知悉后才继续。确认之后仍按位阶作答，
**不提供「按另一份作答」的选项**。

阻断这一轮**不调模型**，成本接近零。

### 三、触发与召回解耦

阻断与否，只看**触发条款自身**对这句提问的「自足分数」，
完全不看它有没有进召回集：

```
阻断 ⟺ max(自足分数 over trigger_clause_ids) ≥ 阈值
        ∧（语境词为空 ∨ 提问命中其中任一）
```

分数是 `max(len(词) ** 1.2 × 字段权重)`，**没有 idf**。

为什么不用 idf：接在 top-N 或文档频率上的话，索引一变大、召回竞争一激烈，
同一句提问就会时而阻断时而不阻断。而阻断是红线级的确定性要求，
**不能随索引规模漂**。压制高频噪声改用一份人工维护、具名采纳、改动须回归的
停用词表（`demo_index/stopwords.yaml`）——它的值只在有人写进那份文件时才变。

## 还有几处是踩出来的

**分词。** 中文原来按 2–6 字滑动 n-gram 切。问「我的包装重金属超标了会怎样？」
被切出 `包装重`——它在提问里跨「包装|重金属」的词界，在另一条讲重复使用的条款标题里
跨「包装|重复」的词界，**两边都不是中文里的词**，字面却一致，于是把那条毫不相干的条款
顶过了冲突闸门；随后冲突关联条款的最高保留优先级又把召回排第一的限值条款挤出了上下文。
**问重金属，答重复使用。** 改成先分词、再在词序列上滑窗，相邻才拼、遇虚词断开。

**裁剪顺序。** 超预算时按「丢了会不会答错」排序丢弃，不按「是不是扩展进来的」。
但光有档位不够——它不区分「派生与来源同时在场」和「来源已经被丢掉」。
补了两条：派生的排序键**挂在来源键之后**（同档时来源必然在前）；
一条位阶 3/4 的解释与它上扩出来的位阶 1/2 法条是**裁剪意义上不可分割的一个单元**。
只改排序，切口落在两者之间时会留下一条没有法条依据的解释；只做绑定，倒挂本身没修。

**基线不许吸收完整失败。** 「已知的可接受损失」这类基线表有个陷阱：
一条用例把期望引用丢光了也能记进去，测试全绿而该用例已经完全失效。
所以另有一条不看基线、直接报错的上限——**单条用例不得丢失其全部期望引用**。

## 跑起来

```bash
docker compose up -d                      # PostgreSQL 16
pip install -r requirements.txt
python scripts/init_db.py
python -m ingest.load                     # 装载 demo_index/
pytest -q                                 # 34 项，不需要模型
uvicorn app.api:app --reload              # http://127.0.0.1:8000
```

前端首屏的动态图谱**画的是真实的条款关系**——节点是已采纳的条款单元、边是登记的
`derogates` / `explains` 关系，沿边跑的脉冲就是一跳扩展的样子。默认只给位阶与拓扑、
不给条款号；**一个节点在本会话的回答里作为引用出现过之后，才获得名字、才可点开**。

问答需要一个模型。`.env` 里给 `ARK_API_KEY`（火山方舟，OpenAI 兼容接口），
或改 `app/providers.py` 换别的——**换模型前先确认它支持等价的严格结构化输出**，
不是「JSON 模式」，否则第一条红线的实现手段就从 schema 保证退化成重试与丢弃。

诊断为什么召回了这些条款：

```bash
python scripts/why.py "包装里重金属最多能有多少？"
```

它会打出候选词、每条召回的来源、三条冲突各自的自足分数与是**哪个词**贡献的，
以及上下文按什么次序保留和丢弃。两次归因错误都是靠它纠正的。

## 这个仓库里没有什么

**索引。** 仓内只有 10 条条款单元的演示切片（`demo_index/`），够把上面每条机制跑出来。
完整索引、工作译本、内部答题纪律、完整用例集与「什么叫答对」的口径不在这里。

这是有意的取舍：**值得看的是机制与纪律，真正花工夫的是内容判断。** 两者可以切开，
所以机制可以公开。
